Security-tests Model Context Protocol (MCP) servers. The extension discovers a server's tools, resources, resource templates and prompts, builds JSON-RPC 2.0 requests with fuzzable insertion points, and runs them through Burp's active and passive scanners. It is intended for operators auditing MCP servers they own or are authorized to test.

Features

  • Connects to modern server/discover HTTP, initialize-based Streamable HTTP and legacy SSE servers, with automatic transport detection and a local proxy so the scanner can handle text/event-stream replies.
  • Handles the authentication your target uses: none, a bearer token, custom headers, or OAuth 2.1 with PKCE, including pre-registered clients, Client ID Metadata Documents and dynamic client registration.
  • Runs scan checks that can be toggled individually, covering unauthenticated request execution, command injection, file path traversal, out-of-band requests, session binding and lifecycle, cross-client response leaks, JWT validation, and OAuth refresh, redirect and authorization flaws.
  • Tests access control between users: define a primary user and compared users, each with their own credentials, owned IDs and private markers, then find where a lower-privilege or anonymous user can call tools or read results that belong to someone else.
  • Sends any discovered tool, resource, template or prompt to Repeater, with the primary user's credentials and session headers applied automatically.
  • Ships with a deliberately vulnerable test server so you can try the checks end to end.

Usage

  1. Open the MCP Server Scanner tab, enter the server endpoint and click Connect. Leave Transport on Auto unless you need to force a protocol.
  2. If the server requires authentication, provide a bearer token, headers or an OAuth sign-in when prompted, or configure users in the Users tab.
  3. Review the discovered tools, resources, templates and prompts, and enable or disable checks in the Scan Checks tab.
  4. Click Scan to run the selected checks. Findings are reported as Burp issues.
  5. To test access control, add compared users in the Users tab, tick the users to compare, then run Check access from the Access tab.

Burp Collaborator is required for out-of-band checks.
