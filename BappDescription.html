Security-tests Model Context Protocol (MCP) servers. The extension discovers a server's tools, resources, resource templates and prompts, builds JSON-RPC 2.0 requests with fuzzable insertion points, and runs its own MCP checks against them, either on its own scan engine or in a Burp audit alongside Burp Scanner's built-in active checks. It is intended for operators auditing MCP servers they own or are authorized to test.

Features

  • Connects to modern server/discover HTTP, initialize-based Streamable HTTP and legacy SSE servers, with automatic transport detection and a local proxy so the scanner can handle text/event-stream replies.
  • Handles the authentication your target uses: none, a bearer token, custom headers, or OAuth 2.1 with PKCE, including pre-registered clients, Client ID Metadata Documents and dynamic client registration.
  • Runs scan checks that can be toggled individually, covering unauthenticated request execution, command injection, SQL injection, file path traversal, out-of-band requests, SSRF filter bypass, Origin/Host admission and CORS, session binding and lifecycle, cross-client response leaks, JWT validation, and OAuth refresh, redirect, consent and authorization flaws, including dynamic client registration that accepts a redirect URI on any host.
  • Optionally tests OAuth consent with your own sign-in: with Burp's cookies for the authorization server, or your browser right after an OAuth sign-in at Connect, it finds consent that is skipped for a signed-in user, remembered by client name, redirect host or client ID prefix, or not asked again for a broader scope. It is off by default and turned on per project with "Test OAuth consent with my sign-in". It registers and deletes probe OAuth clients and may obtain a token in your name, which it revokes.
  • Tests access control between users: define a primary user and compared users, each with their own credentials, owned IDs and private markers, then find where a lower-privilege user, a caller with no credential or a caller with a fake token the server never issued can list or call tools or read results that belong to someone else.
  • Reports each issue with only the exchanges that prove it, as the raw exchange with the target, credentials included, so you can send it straight to Repeater.
  • Sends any discovered tool, resource, template or prompt to Repeater or Organizer, with the primary user's credentials and session headers applied automatically.
  • Settings follow the Burp project; "Save as my defaults" makes new projects start with your own choices.
  • The source repository includes a deliberately vulnerable test server so you can try the checks end to end.

Usage

  1. Open the MCP Server Scanner tab, enter the server endpoint and click Connect. Leave Transport on Auto unless you need to force a protocol.
  2. If the server requires authentication, provide a bearer token, headers or an OAuth sign-in when prompted, or configure users in the Users section.
  3. Review the discovered tools, resources, templates and prompts, and enable or disable checks in the Checks section.
  4. Click Scan to run the selected checks. Findings are reported as Burp issues.
  5. To test access control, open the Access tab, optionally run Collect IDs to gather the IDs each user owns, then run Check access. It always compares with No credential and a Fake token; add compared users in the Users section and tick Compare to include them.

Requirements

Burp Suite Community can connect (including OAuth), browse, ask the server for values and send requests to Repeater and Organizer. Scanning, Check access, Collect IDs and the signed-in consent test need Burp Suite Professional. Burp Collaborator is required for out-of-band checks.

Issue evidence is the raw exchange, so a Burp project file holding these issues can contain tokens and secrets. Treat it as sensitive.
